# 通用文字游戏模板

## 架构目标

同一个 App 通过 `TextAdventureCatalogSO` 管理多个子游戏。工程支持两种互不混用的子游戏内容模式：

- `LegacyNodeAdventure`：运行《抓住未尽的余晖》现有节点、道具和谜题。
- `TextStory`：运行由数据驱动的章节、剧情页、台词和固定选项，适合小说改编。

两种模式共用竖屏高对比度界面、中文字体、读屏焦点和电脑无障碍预览器。App 启动后先选择子游戏，再进入该游戏的开始、继续和返回操作；新小说不需要动画、立绘或背景图。

## 剧情页面顺序

每个页面固定按以下顺序呈现：

1. 章节标题（有章节时）
2. 画面描述
3. 台词或旁白
4. 固定选项，或者“继续剧情”
5. “存档并退出”

`visualDescription` 必填。`artworkPath` 可为空；没有图片时仍显示完整文字，并保留相同的读屏语义与操作顺序。

## JSON 字段

- `schemaVersion`：当前固定为 `1`。
- `gameId`：存档隔离标识，只能使用小写英文字母、数字、点、下划线和连字符。
- `displayName`：游戏名称。
- `protagonistName`：主角名称。
- `firstPageId`：开场页面 id。
- `chapters`：章节 id 和标题。
- `pages`：全部剧情页面。
- `pages[].visualDescription`：必填画面描述。
- `pages[].artworkPath`：可选的 Unity `Assets/...` 图片路径。
- `pages[].lines`：说话者和文字。
- `pages[].nextPageId`：线性页面的下一页。
- `pages[].choices`：分支选项；存在选项时不能同时设置 `nextPageId`。

完整例子见 `ContentImports/示例文字游戏.json`。

## 导入与校验

Unity 菜单提供：

- `工具/文字游戏/导入剧情 JSON`
- `工具/文字游戏/校验选中的游戏定义`
- `工具/文字游戏/将选中定义添加到子游戏目录`

自动化导入可以调用：

```powershell
$env:TEXT_ADVENTURE_JSON='外部小说转换后的剧情.json'
$env:TEXT_ADVENTURE_ASSET='Assets/GameContent/Generated/new-game.asset'
$env:TEXT_ADVENTURE_ADD_TO_CATALOG='1'
Unity.exe -batchmode -projectPath . -executeMethod TextAdventureGameImporter.ImportFromEnvironment -quit
```

追加子游戏只更新目录资源，不修改 `PlayerSettings.productName`、Android 包名或 App 身份。相同 `gameId` 不能指向两个不同资源；每个子游戏根据 `gameId` 使用独立存档。正式目录是 `Assets/GameContent/GameCatalog.asset`，示例资源默认不加入目录。

导入器会拒绝以下内容：重复或空 id、缺少画面描述、空台词、无效分支目标、线性下一页与选项并存、无法从开场到达的孤立页面。

## 从小说生成

小说原文不能直接机械复制进游戏。自动改编流程应先输出符合上述结构的 JSON，并在导入前完成：人物名统一、说话者识别、章节和场景切分、画面描述补充、过长段落拆分以及分支目标检查。导入后的 Unity 资源不依赖原始小说文件的绝对路径。
